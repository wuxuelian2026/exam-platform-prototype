# 移动端舞蹈入场分组展示

## 页面变更

- 考生端：我的考试 → 考试详情 → 考试安排，增加“入场分组”，展示本人的组名、组内序号和组人数，不展示其他组员个人信息。
- 教师端对应当前原型的考官端：排期 → 场次详情 → 考生名单，每位线下舞蹈考生增加“入场分组”；进入个人评分页仍可查看相同字段。
- 仅线下舞蹈门类展示。缺少分组显示“待分组”；线上舞蹈及非舞蹈隐藏字段；切换记录时清除上一条分组内容。
- 组内序号与原有场次序号分别展示。允许同专业混级、人数不限，不从级别或名单行号自动推算组别，逐人评分流程不变。

## 数据口径与演示入口

- 两端使用统一展示函数，读取当前报名/个人评分任务的 `entryGroup: { id, name, memberOrder, memberCount }`。该字段应来自后台已发布排期中的人工分组快照，`id` 为稳定组标识，名称及序号按已发布版本更新；组人数和组内序号可选，缺失不编造。
- 当前是独立前端演示数据：考生端已有中国舞考试详情配置已分组样例；“昨天”“明天”的舞蹈考试也有分组样例，其余无分组的舞蹈记录展示待分组。
- 考官端新增“今天”的“中国舞 · 今日评分场”（`dance-afternoon`），10名考生按2级3人、3级4人、5级3人配置，第1组7人（2级与3级混级）、第2组3人（5级）。用于展示逐人的组别及评分入口。
- 本次不新增后台实时同步接口，不把尚未发布的后台分组草稿直接对考生公开；不改动 test 环境。

## 验证范围

- 三个舞蹈专业、混级分组、缺失分组、部分元数据、线上舞蹈和非舞蹈、记录切换残留、纯文本安全展示、个人评分入口及两端脚本语法。
