# 舞蹈考试编组双模式（现场按到场顺序发号）

日期：2026-11-09

## 背景

后台此前已有「提前编组」（人工勾选舞蹈考生入场分组）。本次在同一抽屉内接入「现场编组」模式，形成提前编组 / 现场编组两种模式。

## 确认口径（现场编组）

- 号牌预印，只印「组号-编号」不印姓名，按顺序叠放如撕票本（1组1号～k组N号）。
- 现场设发号台：发号员登录「场次发号员」受限账号（绑定手机号、当场次有效、权限仅扫码出号与撤回），扫考生准考证码后系统提示应发号，发号员从套顶撕下对应号牌递出并点确认，即同时完成签到与号牌绑定。
- 累计满 N 人自动开新组，组内编号自 1 连续递增，末组按实际人数成组；号码一经发出不重排（撤回仅作废不复用，重新扫码取新号）。
- N 取「机构×场次」维度（场次可被多家机构共用），取值 1～30，按专业给默认值（舞蹈 10、其余 1）；N=1 不生成号牌，按单人入场。
- 按到场顺序出号，迟到者自然取得后续号，现场不存在换组环节；缺席者未发牌即未到场，无需另行登记缺考。
- 发号台归属：单机构场次由机构带队老师发号；混编场次由承办单位/考点统一发号。机构带队老师只负责带学生到发号台排队，考官不参与进场。
- 考场网络良好，不做离线缓存与补传。

## 原型变更（current/admin/index.html）

1. 场次操作入口由「入场分组（N组）」改为「考试编组 · 现场 / 提前 N组」，抽屉更名「考试编组（舞蹈）」，顶部提供 提前编组 / 现场编组 模式标签。
2. 现场编组页包含：编组方案（机构×场次参数表：每组人数 N、预计组数、组号段、号牌套张数、发号归属）、号牌套预印清单与导出（CSV）、**现场发号进度（只读）**、场次发号员授权（新增/撤回，含登录手机号与登录方式）。发号动作不在后台操作，详见下方「11:30 修订」。
3. 保存：提前编组保存 entryGroups 并标记 groupingMode=pre；现场编组保存 groupingMode=live 与 liveGrouping（参数、发号流水、发号员），并写入批次变更记录。
4. 发布/提交校验：groupingMode=live 的场次不参与提前分组完整性校验（分组在现场完成）。
5. 演示数据：batch-demo-05 混编舞蹈场次（光谷 1 人 + 汉口 30 人）默认展示现场编组，混编场景由承办单位/考点统一发号。
6. 已有发号记录后 N 锁定不可修改（号码不重排）。

### 角色与登录

- 后台不做发号，只做**场次发号员授权**：新增/撤回发号员，登记授权登录手机号，登录方式为短信验证码（受限账号，仅本场次有效，权限只有扫码出号与撤回，不能改名单或评分）。

### 现场发号流程

1. 考前后台设 N（机构×场次）、导出号牌套（只印组号-编号，不印姓名），号牌按序叠放如撕票本。
2. 现场考生到场：发号员扫准考证二维码（原型支持输入报名编号/姓名定位）→ 工作台显示「下一位应发号码」及对应号牌套张序。
3. 撕下对应号牌递出 → 点「确认发号」→ 实时写入场次发号流水，同时完成签到与号牌绑定。
4. 满 N 自动开新组；撤回只作废、号码不复用；未发号即未到场，不另登记缺考；号码不重排。

## 15:44 修订：绑定消费后清空搜索词，避免列表残留复现

15:30 联调时发现：模糊词「汉口」发号后 `scannedCandidateId` 已复位，但搜索词仍在，`needPick` 重新成立，列表又会铺出剩余 7 人；输入完整报名编号发号后更会残留一条「没有匹配的考生」空态，与「默认不铺名单」的口径冲突。

### 改动（current/student/index.html）

