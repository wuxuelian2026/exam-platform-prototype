# 批次工作台平台、承办单位代操作权限调整

日期：2026-10-20

分支：`v1.120261019需求变更`

## 需求口径

本次用户明确要求优先于旧版按钮权限表中与本次冲突的规则：批次工作台内，平台与承办单位的功能按钮权限一致，只有制证操作仅限平台。平台或承办单位可在各自数据范围内代下级培训机构操作。培训机构自身权限不因此扩大。

范围仅为 `current/admin/index.html` 的批次工作台及其复用抽屉；不调整独立单位审核、计划审核、课程、师资培训等模块的角色规则，不修改测试环境角色或后端。

## 阶段处理

| 阶段 | 平台、承办单位的按钮口径 | 保留的业务约束 |
| --- | --- | --- |
| 线上、线下报名 | 新增、导入、单条/批量确认缴费、取消订单、发起退款、确认退款及原有查询导出入口 | 订单状态、退款原因、金额及凭证校验；冻结保护 |
| 线下排期 | 创建/编辑/删除场次、分配/移出考生、人工入场分组、提交排期、复核发布 | 编排阶段方可维护；待复核方可发布；已发布只读；覆盖及冲突校验不变 |
| 线下准考证 | 两类角色使用相同生成、发布等既有入口 | 排期发布前不开放；生成完整性及重生成校验不变 |
| 线上录制 | 保持后台既有视频状态查询与流程入口一致 | 不增加后台替考生录制或提交视频功能，不增加线上排期 |
| 线上、线下派遣 | 指派、调整、发布等入口一致；移除承办单位被底层写入检查误拦截的限制 | 培训机构仍只读，冻结及前置阶段限制不变 |
| 线上、线下成绩 | 设置考评成绩、发布、导出等既有入口一致；承办单位可进入发布确认并执行发布 | 评分未完成、评级缺失、待补正、无待发布记录等情形仍阻断 |
| 证书 | 制证写操作仅平台；承办单位保留证书库查询等原有只读入口 | 生成、清号、提交入库、作废等制证写操作不向承办单位开放 |
| 批次统计 | 维持两类角色既有查询、导出入口 | 不扩大数据查询范围 |

## 数据与执行校验

1. 报名按钮展示、打开抽屉、确认执行及批量缴费均检查报名所属单位，而非创建人。平台可操作全平台，承办单位限本单位及下级，培训机构限原有组织范围。
2. 原型部分自动生成的模拟机构名称不在单位树内：仅当模拟机构属于该批次明确的模拟机构名单，且该批次所属单位在承办单位范围内，才允许承办单位操作。此为原型模拟数据兼容，不是生产环境按名称授权方案。生产实现应使用真实组织 ID、业务归属关系校验。
3. 排期代操作链接中的 `scheduleOrg` 仍受组织范围校验，不能通过改链接代其他辖区机构操作。
4. 批量缴费若混入范围外记录，整批拒绝；抽屉打开后再次确认也重新校验。
5. 人工分组、场次保存、考生分配共用可写校验；已发布和冻结状态不因角色放开而绕过。
6. 本次修改是交互原型，不构成后端安全授权；研发仍须对每个写接口校验功能权限、业务归属、业务授权和数据范围。
