# 批次计划所属单位调整

- 评审来源：用户要求新建批次的“承办单位”改为“所属单位”，可选平台、承办单位、培训机构，范围仅限本单位及下级。
- 涉及页面：后台批次计划新增/编辑、计划列表及审核列表、批次基本信息和相关归属摘要。
- 变更原因：支持上级代下级录入，归属单位不再限定为承办单位。

## 规则

- 复用单位管理中的单位树，按当前登录单位 ID 计算本单位及全部下级单位；上级、平级和其他分支不进入可选列表。
- 所属单位按平台、承办单位、培训机构分组，默认选中当前单位；不在三类范围内的部门不能成为所属单位。
- 选择值使用单位 ID，保存保留原有单位名称字段 `org`，并写入 `ownerOrgId` 和 `ownerOrgType`。
- 线上、线下批次的保存草稿、提交审核和发布操作均校验所选单位仍在允许范围内；无效选择阻断保存。
- 编辑时按单位 ID 回显；历史批次只有名称时按当前可选单位兼容匹配。超范围或已移除的单位不自动替换为当前单位。
- 所属单位类型不等于当前用户角色：本次不扩大培训机构的新建、审核、发布等功能权限，也不调整报名机构等其他配置的授权范围。

## 影响范围与验证

- 同一归属字段在列表、审核列表和详情中统一显示为“所属单位”；承办单位的角色名称与业务流程文案保持不变。
- 新增 10 项自动化检查，覆盖三种角色范围、层级递归、会话单位、非法选择阻断、线上/线下保存和历史回显。
- 浏览器验证平台选择培训机构后保存和编辑回显、承办单位范围和必填阻断均通过。
- 仅本地前端原型，不接真实后端；提交分支为 `v1.120261019需求变更`，不推送或变更 Pages。
